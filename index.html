3．Codexが自動化・実行するべきテスト

不具合を減らすため、実装と同時にテストコードを作成し、CIで毎回実行します。

Codexへの必須指示：テストを通すために機能を無効化したり、失敗テストを削除してはならない。失敗原因を修正し、全テスト、型チェック、静的解析、ビルドを再実行する。

GitHub Actions / CIで毎回実行する順序

  1. 依存関係インストール（lockfile固定）
  2. フォーマット確認
  3. 静的解析
  4. 型チェック
  5. 単体テスト
  6. 結合テスト
  7. 本番ビルド
  8. E2Eテスト
  9. 依存関係・秘密情報・脆弱性監査

マージ条件：すべて成功し、重大・高リスクの脆弱性がなく、失敗テストやスキップされた必須テストがないこと。
